Programmable Logic Controller

The PLC runs one ELCL program over and over, with six redstone faces, four sensor module slots and its own green screens, on its own or as a network device.

The Programmable Logic Controller (PLC) is a wall-mounted controller that runs one compiled ELCL program continuously, the way an industrial PLC runs its scan. It has the six redstone faces of a Control Interface, four slots for sensor modules, and its own green screens for status, I/O, modules and editing. It works entirely on its own from a small FE buffer, or as a device on a network, where its program can use every ELCL command.

This page covers the block. How to write programs for it is on Redstone, PLCs and signals from ELCL.

Placing and powering it#

Place it on a wall and it faces out from it (anywhere else it faces you). The block is a steel backplate with a DIN rail, the CPU module (its LCD, RUN and ERROR LEDs and an I/O LED for each face) and four module slots beside it.

On its ownCabled to a network
HowNothing cabled to itA cable on any face except its front
Powerplc.plcEnergy (default 2) FE a tick from its own buffer of plc.plcBuffer (default 1000) FE, filled with FE from any faceThe network powers it; it is a device with one lane

What its program can doThe language itself, its own faces and its modules (see Programs)Every ELCL command

With no power it goes OFF: its outputs go dark and the program halts. When power comes back it runs again from the top, if it was running. A world reload counts as a power-up.

Breaking a PLC keeps its program and its device name on the item; its modules drop separately. Placing a PLC item that carries a program puts the program back.

Modes#

ModeWhat it means
OFFNo power: outputs dark, program halted
STOPPowered but not running; its outputs are cleared
RUNRunning its program; each face's I/O LED lights for 10 ticks after that face's level changes
FAULTThe program failed (see Faults); the ERROR LED shows it

F6 (or STRPLC) runs it and F7 (or ENDPLC) stops it.

The scan#

The program runs continuously, plc.plcInstructionsPerTick (default 50) instructions a tick. A pass that needs more carries on next tick. When it reaches ENDPGM, the next pass starts from the top on the next tick, with every variable carrying its value over from the last pass: a variable's VALUE() is set only when the PLC goes from STOP to RUN and at power-up. The status screen shows the scan time (ticks a pass takes) and the instructions a tick against the budget.

Variables declared with RETAIN(*YES) are kept in the program itself, so they survive STOP and RUN, power loss, world reloads, and being saved to a cartridge or carried on the item. Option 6 on the status screen lists them.

Faults#

An escape message the program doesn't monitor (with MONMSG) puts the PLC in FAULT. The message, its text and the line it came from show on the status screen and the LCD. What the outputs do then is set by the server:

plc.plcFaultOutputsOutputs on FAULT
HOLD (the default)Keep their last levels
ZERODrop to 0

F9 on the status screen (or STRPLC) clears the fault and runs the program from the top. STOP clears the outputs.

Sensor modules#

Use a module on the PLC to put it in the first free slot; sneak-use the PLC with an empty hand to take the last one out. Each reading gives a value, a status (*OK, *NOMODULE or *NOTARGET) and an extra ("aux") value:

ModuleTYPE()ReadsValueAuxSetting
Presence Sensor*PRESENCEPlayers or mobs within its radiusHow manyThe nearest one's nameRadius 1-16 (default 8); *PLAYERS (default), *MOBS or *ALL
Inventory Sensor*INVENTORYThe container on its facePercent full (by slot, as a comparator reads it)Item countThe face (default: behind the PLC)
Fluid Sensor*FLUIDThe tank on its facePercent fullAmount in mBThe face (default: behind the PLC)
Light Sensor*LIGHTThe light level at the PLC0-15*DAY or *NIGHTNone
Timer Module*TIMERThe game clockGame ticksThe day and time, such as Day 2 14:32None

The Timer Module reads the game's own clock, not real time. A program reads a module with RTVSNSVAL:

DCL VAR(&N) TYPE(*INT)
DCL VAR(&S) TYPE(*CHAR) LEN(10)
RTVSNSVAL MODULE(1) RTNVAL(&N) RTNSTS(&S)     /* a Presence Sensor in slot 1 */
IF COND(&S *EQ '*OK' *AND &N *GT 0) THEN(CHGRSOUT DEV(*SELF) SIDE(*UP) LVL(15))
ELSE CMD(CHGRSOUT DEV(*SELF) SIDE(*UP) LVL(0))

Without RTNSTS, a missing module is ELC1501 and a module with nothing to read is ELC1503.

The modules' recipes are a Circuit Substrate and a Logic Die with one more part each: a stone pressure plate, a comparator, a bucket, a daylight detector or a clock.

The PLC's screens#

Right-click the PLC to open its screens. Who may open them:

  • On a network: players with the Firewall's BUILD permission (everyone, without a Firewall).
  • On its own: anyone. With plc.plcOpenToAnyone set to false, only the player who placed it and server operators.

The screens are green screens like the Terminal OS, with the same keys:

ScreenTitleWhat it shows
PLCSTSPLC StatusThe PLC, its network, program and size, mode, scan time, instructions a tick, who loaded the program (and their authority), power, and the last error. The menu below
PLCIOPLC I/O TableEach face's input and output and what drives it: the CHGRSOUT line that set an output, or the block next to a face giving it its input. Live, with level bars, refreshed every 10 ticks
PLCMODPLC ModulesEach slot's module, setting, value and status. 2=Change setting (radius and what it counts, or the face; F4 lists the values), 4=Remove module
PLCRTNPLC Retained VariablesThe program's RETAIN(*YES) variables, and the PLC's log: its SNDPGMMSG messages and escapes (16 entries)

PLCSTS's menu: 1 Edit program, 2 Display I/O table, 3 Display modules, 4 Save program to cartridge, 5 Load program from cartridge, 6 Display retained variables. Keys: F6 Run, F7 Stop, F9 Clear fault, F10 I/O table, F11 Modules, F12 back. On a PLC cabled to a network, anything else typed on PLCSTS's command line runs as an ELCL command on its network; on one that isn't, only 1-6 work there.

The editor#

Option 1 opens the program in the Terminal OS source editor, as member *PLC/<program> (a new PLC's program is called PLCPGM). It has the editor's syntax check, F4 prompter and command line, and it checks the program for this PLC: on its own, a command that needs a network is flagged (ELC1502). Saving sends the source to the PLC, which compiles it. An error shows on its line; when the program goes in you get ELC0213, and the PLC restarts it if it was running. Leaving the editor goes back to PLCSTS.

Getting a program onto a PLC#

There are four ways:

  1. Write it on the PLC: PLCSTS option 1, above.
  2. From an EEPROM Cartridge: hold a cartridge and use PLCSTS option 4 to save the PLC's program (with its retained variables) onto it, or option 5 to load the cartridge's program into the PLC. Loading stops the PLC; F6 runs the new program. Only one cartridge of a stack is written. The cartridge has no slot: it is used from your hand.
  3. From a library, over the network: compile the program for a PLC with CRTELPGM TGT(*PLC), then send it with SNDPLCPGM PGM(MYLIB/DOORCTL) DEV(PLC01). A program not compiled for a PLC is ELC1504. The PLC stops first, then runs from the top (unless RUN(*NO)). Sending the same program again keeps its retained variables.
  4. On the item: a PLC you broke carries its program; place it again.

The EEPROM Cartridge is either blank or carries a program, and its tooltip says which.

Whoever loads a program (by any of these ways) becomes its loader. On a network the program runs with the Firewall authority of that player, as PLCSTS shows. On its own a PLC's program may do everything it can run.

What a program can do without a network#

On its own a PLC runs the language statements (PGM, DCL, CHGVAR, IF, the loops, SELECT, subroutines, MONMSG, RCVMSG, SNDPGMMSG ...), the list commands, DLYJOB, DLYTICK, its modules (RTVSNSVAL) and its own faces (RTVRSIN and CHGRSOUT with DEV(*SELF); DEV is required on both). Anything else is ELC1502, both when you save it and at run time. Cabled to a network, every command works, and its messages go to the PLC's own log. Redstone, PLCs and signals from ELCL has the full list and examples.

A program that counts button presses on one face and mirrors the button onto another:

PGM
  DCL VAR(&IN) TYPE(*INT)
  DCL VAR(&OPENS) TYPE(*INT) RETAIN(*YES)    /* counted across STOP / RUN and reloads */
  DCL VAR(&WAS) TYPE(*INT)
  RTVRSIN DEV(*SELF) SIDE(*WEST) RTNLVL(&IN)  /* a button on the west face             */
  IF COND(&IN *GT 0 *AND &WAS *EQ 0) THEN(CHGVAR VAR(&OPENS) VALUE(&OPENS + 1))
  CHGVAR VAR(&WAS) VALUE(&IN)                 /* kept from scan to scan                */
  CHGRSOUT DEV(*SELF) SIDE(*EAST) LVL(&IN)    /* the door on the east face             */
ENDPGM

Limits#

At most plc.plcMaxPerChunk (default 16) PLCs run in one chunk and plc.plcMaxPerServer (default 512) on the whole server. Another one stays in STOP, with the note "PLC limit reached" on its status screen, until there is room. See Performance and limits.
