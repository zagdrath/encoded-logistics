Control Interface

A network device with six redstone channels, one per face, that ELCL reads with RTVRSIN and drives with CHGRSOUT.

On this page

  2. The six channels
  3. How the output behaves
  4. Errors
  5. LEDs
  6. Reacting to changes
  7. Permissions

The Control Interface gives ELCL redstone input and output. Each of its six faces is a channel of its own: it reads the redstone level arriving on that face and can give out a level of its own there. It has no screen; you drive it from a terminal or a program.

Putting one on a network#

Cable it to a network like any other device. It takes one lane and drains reach.controlInterfaceDrain (default 1) FE/t while its network runs, and it is online while its network is.

The first time it is on a network it takes the lowest free name of the form CTLIFnn (CTLIF01, CTLIF02, ...) and keeps it, on its item too when you break it. RNMDEV or Work with Devices (WRKDEV) option 2 renames it. It appears under that name in Work with Devices and in the prompter's device list.

The six channels#

The faces are *NORTH, *SOUTH, *EAST, *WEST, *UP and *DOWN, and each has an input and an output level from 0 to 15.

ToCommandNotes
Read a faceRTVRSIN DEV(CTLIF01) SIDE(*NORTH) RTNLVL(&L)SIDE(*MAX) gives the highest of the six
Drive a faceCHGRSOUT DEV(CTLIF01) SIDE(*UP) LVL(15)SIDE(*ALL) sets all six; a level outside 0-15 is ELC0004
DCL VAR(&L) TYPE(*INT)
RTVRSIN DEV(CTLIF01) SIDE(*MAX) RTNLVL(&L)       /* the strongest signal coming in */
IF COND(&L *GE 8) THEN(CHGRSOUT DEV(CTLIF01) SIDE(*ALL) LVL(15))
ELSE CMD(CHGRSOUT DEV(CTLIF01) SIDE(*UP) LVL(0)) /* top face off                   */

At the ===> prompt you can leave the keywords out: RTVRSIN CTLIF01 *MAX shows RTNLVL = 9 on Command Entry, and CHGRSOUT CTLIF01 *ALL 15 turns every face on at full strength.

How the output behaves#

  • Weak power only. A face powers what is directly next to it (a lamp, dust, a repeater), but it never strongly powers a solid block there, so it doesn't reach through that block to things beyond it.
  • It never reads itself. A face's input is only what something else gives it. Redstone dust that the interface powers itself only counts when something else drives that dust higher.
  • Offline. While its network is down it gives out nothing, but it keeps its output levels (they are saved with the block) and gives them out again when it is back online. While it is offline both commands answer ELC1302, and CHGRSOUT stores nothing.

Errors#

A name no device has is ELC1301; a device that isn't a Control Interface (or a PLC, which has the same faces) is ELC1303.

LEDs#

Each face has an LED showing the higher of what comes in and what goes out there: off (0), dim (1-7) or bright (8-15).

Reacting to changes#

When the level arriving on a face changes, the interface fires a *RSCHANGE trigger event, once per change, with its device name and &DATA such as *NORTH 7 (the face and the new level). A trigger added with ADDTRGEVT EVENT(*RSCHANGE) on it (for one face only: VALUE(*NORTH)) runs its program then, so you don't have to poll. See Jobs, scheduling and triggers for triggers.

Permissions#

On a network with a Firewall, RTVRSIN needs the VIEW permission and CHGRSOUT needs BUILD (the commands' CONFIGURE authority). See Firewall and security.

For a block that runs its own program next to the redstone, with no terminal involved, use a Programmable Logic Controller.
