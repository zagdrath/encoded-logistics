Configuration

Where the mod's two config files are, how they apply, and a guided tour of the options a server owner is most likely to change.

Encoded Logistics has two config files. This page says where they are and walks through the options that matter most; Config options lists every one of them with its type, default, range and description.

The files#

FileWhat it holdsWhere it applies
config/encodedlogistics-local.tomlEverything about how the mod behaves: power, lanes, storage, crafting, racks, routing, the Terminal OS, PLCs, displays, speakers (13 sections)On the server (and in single-player, the game you play)
config/encodedlogistics-client.tomlOne player's own preferences: terminal sorting and layout, job toasts, web audio, UPS alarm sounds (3 sections)On that player's game only

Things to know about the main file:

  • It is per installation, not per world. It sits in the game's (or the server's) config/ folder and applies to every world that installation opens. There is no copy in the world's save, as some mods' server configs have.
  • It is not sent to players. On a dedicated server the server's file is the one that counts. A player's own copy of encodedlogistics-local.toml doesn't change the server, though a few item tooltips and screens on that player's game read numbers from their own copy, and may differ from the server's if the two files differ.
  • Older betas. On NeoForge betas before 26.3.0.37 the same file is called encodedlogistics-common.toml.
  • Editing. Edit the file with the game or server stopped, or use the in-game config screen (Mods, Encoded Logistics, Config) in single-player. None of the options is marked as needing a restart.

The files are written with every option and its comment the first time the game starts with the mod.

A guided tour#

The sections in the main file are controller, lanes, power, storage, autocrafting, reach, lithography, facades, rack, optical, elcl, plc and signals. The rack section holds more than racks: routing, the UPS, wireless, Arcforge machine power, the Midrange line, disk and tape drives, Display Panels and the Terminal Desk all live there. The groups below are by feature, with each option's real path.

Security#

Whether an offline Firewall still enforces its rules, and how a Server Rack is protected from being broken. See Permissions.

OptionTypeDefaultAllowedConfig screenWhat it does
rack.firewallFailClosedbooleantrueOffline Firewall Still EnforcesWhether a Firewall that's offline (no lane, no power) still enforces its rules.
rack.rackBreakProtectionbooleantrueWhether breaking a Server Rack (and so pulling its devices out) needs the Firewall's rack access permission on its network.
rack.rackBreakConfirmbooleantrueWhether breaking a Server Rack takes a sneak, or a second left click within a second of the first, so a stray click can't start taking one down.

The budgets are explained on Performance and limits, folder sync on Folders on disk, and what the limits mean for programs on Limits and behaviour to know. Two more options elsewhere in the file belong with these: reach.controlInterfaceDrain (the Control Interface's power use) and rack.firewallFailClosed.

Files players can add: images and audio#
