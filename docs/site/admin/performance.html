Performance and limits

Every budget and limit that keeps the mod's cost on a server bounded - ELCL, PLCs, Display Panels, Speakers, networks and chunk loading - and the options that set them.

On this page
  1. ELCL programs
  2. PLCs
  3. Display Panels
  4. Speakers and Alarm Strobes
  5. Networks
  6. How often networks are worked out
  7. Checking the network caches
  8. Chunk loading

Most of what Encoded Logistics does on a server is bounded by a budget or a limit, so one player's program, screen or speaker can't take the server down. This page gathers them in one place. The defaults suit a small server; raise them with care. The numbers that aren't options are fixed in the code.

ELCL programs#

Programs run a few instructions at a time, taking turns:

OptionWhat it limits
elcl.interactiveBudget (default 200)Instructions an interactive job (a program called from a terminal) runs each tick before it yields
elcl.batchBudget (default 100)Instructions each batch job runs each tick
elcl.globalBudget (default 2000)Instructions all jobs on the server run each tick, together. Jobs take turns, so the cap is shared out fairly

A job that is waiting (DLYJOB, a recall, a craft) costs nothing. An endless loop only ever uses its budget, and can be ended from Work with Active Jobs. How many batch jobs run at once is set per system by the QMAXJOB system value, and per host by elcl.computeServerJobs (default 4) (jobs each Compute Server runs; 0 makes Compute Servers no job hosts at all).

What a system keeps:

OptionWhat it limits
elcl.maxSourceLines (default 5000)Lines in a source member
elcl.maxListSize (default 4096)Elements in a *LIST variable
elcl.maxRecordsPerFile (default 10,000)Records in a physical file (ELC2208 past it)
elcl.spooledFileCap (default 200)Spooled files a system keeps (the oldest go first)
elcl.messageCap (default 500)Messages each user's queue keeps (the oldest go first)
elcl.craftLogRetention (default 200)Ended crafting jobs each network's history keeps, by default (the CRFLOGRTN system value)
elcl.disketteBytes (default 65,536)Bytes of library source an 8" Diskette holds
elcl.charsPerStorageByte (default 64)Characters of source that take one byte of the network's drive storage

In the code: a program declares at most 5 files (DCLF).

PLCs#

OptionWhat it limits
plc.plcInstructionsPerTick (default 50)Instructions a PLC runs each tick (a scan that needs more carries on next tick)
plc.plcMaxPerChunk (default 16)PLCs running in one chunk
plc.plcMaxPerServer (default 512)PLCs running on the server

A PLC over either limit stays in STOP ("PLC limit reached") until there is room. Each PLC's log keeps 16 entries.

Display Panels#

OptionWhat it limits
rack.displayMaxWidth (default 8), rack.displayMaxHeight (default 6)A screen's size in panels
rack.displayHistorySeconds (default 600)Seconds of graph history a screen keeps itself
rack.displayMaxImageBytes (default 4)An image file's size, in MB
rack.displayMaxImageSize (default 4096)An image's width and height, in pixels
rack.displayMaxImagePixels (default 16,777,216)An image's width x height
rack.displayImageColors (default 256)The most colours a player may pick for an image

In the code: at most 16 regions a screen, 64 rows in a table widget, four touches a second for each player, and a wall of at most 1,024 panels is merged at once. Live widgets are worked out once a second, only for players near the screen. Images are decoded off the server thread, at the region's size, and cached.

Speakers and Alarm Strobes#

OptionWhat it limits
signals.audioMaxBytes (default 4)An audio file (or web audio), in MB
signals.audioMaxSeconds (default 180)An audio file's length, in seconds
signals.midiMaxKilobytes (default 256)A MIDI file, in KB
signals.midiMaxSeconds (default 600)A MIDI file's length, in seconds
signals.midiMaxNotes (default 8)Notes one Speaker starts in a tick from a MIDI file (the loudest are kept)
signals.speakerMaxRange (default 64)How far a Speaker may be set to carry
signals.sirenMaxRange (default 96)How far an Alarm Strobe may be set to carry

In the code: files go to players in 24 KB chunks, four a tick for each player and one file at a time; players keep at most 64 MB of audio in memory; the server remembers its last 256 checked files; a note sequence has at most 32 notes and a MIDI play at most 32 parts; a web fetch gives up after 30 seconds.

Networks#

OptionWhat it limits
controller.maxSize (default 7)A Network Controller structure's size along each axis
autocrafting.schedulerMaxSize (default 7)A Scheduler structure's size along each axis
lanes.perControllerFace (default 32)Lanes each connected controller face provides
lanes.perCable (default 8), lanes.perDenseCable (default 32), lanes.perFiberCable (default 32)Lanes a cable carries
storage.driveTypeLimit (default 63)Item types on one Storage Drive
rack.directoryCacheSeconds (default 30)How long a resolved SYSNAME/DEVICE name is kept
rack.maxHops (default 16)Hops a dynamically routed path may take

Lanes are what limit how many devices a network runs; see Lanes.

How often networks are worked out#

A network rediscovers its blocks and works out its lanes again (a solve) only when something it's made of changes: a block placed, broken or reconnected on it or next to it, or a remote link to it coming up or going down. A remote link's end loading or unloading as players move about costs nothing unless the link really changed. A burst of changes costs one solve:

OptionWhat it does
lanes.resolveInterval (default 20)Ticks a network waits after a solve before it solves again; changes in the meantime are gathered into one. 0 solves after every change
lanes.slowSolveMillis (default 50)A solve slower than this many milliseconds is logged as a warning, with the network and its cause; 0 logs none

/encodedlogistics debug solves shows each network's solves over the last minute, what they cost and what caused them, debug ticks what the networks cost every tick, and debug watch solves shows slow solves in your chat as they happen. See Server commands.

Checking the network caches#

Networks keep caches (their storage, drive cells, the rack devices serving them, racks in order and the rack Scheduler pools) and rebuild them only when something changes. If a server lags around a large network, /encodedlogistics caches shows how often each was rebuilt over the last minute. A cache rebuilt about every tick (some 1,200 a minute) means something invalidates it every tick. See Server commands.

Chunk loading#

Only two things load chunks:

OptionWhat it loads
reach.bridgeChunkLoading (default false)A linked Network Bridge keeps its own chunk loaded, so its partner's network reaches it while nobody is near
rack.exchangeChunkLoading (default true)An Exchange Switch keeps its chunk loaded while it has members

Everything else works only while its chunk is loaded by players or another mod.
