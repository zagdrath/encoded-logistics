Limits and behaviour to know

The Terminal OS's and ELCL's limits, and the places where they behave in ways you might not expect.

The Terminal OS and ELCL are complete: every command in the command reference and every message in the message reference works as its page describes. This page gathers the numbers that bound them and the behaviour that most often surprises people. The server options that set many of these numbers are on Server configuration (the elcl and plc sections).

Known limits#

Jobs#

  • Batch jobs end when their host goes down. A job's state is saved with the system, but no job host carries a job on: when a Compute Server or Midrange System goes offline (unloaded, removed, out of power, an IPL) or the server restarts, its running batch jobs end with ELC0310. Queued and held jobs wait. Use a schedule entry or a trigger for work that has to start again by itself.
  • Interactive jobs aren't saved. A program called from a terminal ends when its terminal closes or the server stops; use SBMJOB for anything long-running.
  • Game time. DLYJOB DLY() counts game seconds (20 ticks each), so it stretches when the server lags; schedule entries with FRQ(*INTERVAL) count real seconds. On a command line DLYJOB and DLYTICK complete at once.
  • No message waits for a reply. Every message is informational or an escape; nothing stops a job to ask.

Triggers#

  • Declare &EVENT LEN(12). The event name arrives whole, and the longest, *SUPFAILOVER, has 12 characters. A shorter variable cuts it: in a LEN(10) &EVENT, *DEVOFFLINE arrives as *DEVOFFLIN, *PWRRESTORED as *PWRRESTOR, *SUPFAILOVER as *SUPFAILOV and *PROTSWITCH as *PROTSWITC.
  • Device statuses aren't saved. The *DEV... triggers compare each device with how it was half a second before; after a restart the first look only records them, so a change while the server was down doesn't fire.
  • A condition that already holds doesn't fire. A new trigger (and every polled trigger after a restart) first records whether its condition holds; it fires the next time the condition becomes true.

Security and authority#

  • *SECOFR is the Firewall's owner and the server's operators. On a network without a Firewall everyone has full authority, so anyone may change system values there, and the Sign On screen appears only when the network has a Firewall and SECLVL is 30.
  • Reading files. Every library gives the public *USE, so any user may read any library's files; only ELSYS's system files are guarded (by the Firewall's view permission). There is no *EXCLUDE authority: CHGLIB AUT() takes *USE and *CHANGE.
  • Commands with no Firewall permission. The display commands (SNDDSPTXT, CLRDSP, CHGDSPRGN, SNDDSPWDG, SNDDSPGPH, SNDDSPIMG, RTVDSPSIZ), the print commands (PRTTXT, PRTRPT) and the OS commands need no Firewall permission: any user's program can drive any Display Panel and printer on the network. The OS commands check the OS's own authority instead (libraries, jobs and system values). The command pages show each command's permission.

Storage and data#

  • Source storage is counted, not reserved. Members count against free drive space (ELC0207 stops a save that doesn't fit), but items going into the network don't check for them, so items can fill the drives past the members' share. See Storage cost.
  • Long records in Update Data. A record whose values add up to more than 8,000 characters can't be sent from the Update Data screen; change it with a program. Long values scroll in their field.
  • Item tiers. There is no tier stored on each item: CHGITMTIER works through the Tape Libraries' keep-hot, pin and archive lists. See Hot and cold storage.

Names and text from the server#

  • %NAME on dedicated servers. Item names are worked out on the server, which may not have a mod's translations, so %NAME of a mod's item can come back as its translation key (item.encodedlogistics.logic_die). The reason in a *CRFSTALL trigger's &DATA is worked out the same way.
  • Device names are given by the mod (CTLIF01, CMPSRV01...) and changed with RNMDEV or Work with Devices option 2.

Things accepted but not used#

  • SNDMSG TOTRM() and WRKINV FILTER() are accepted and ignored.
  • DATFMT changes the dates the system writes, not the screen header's clock, which always shows "Day n".
  • Spooled files have the statuses *RDY, *PRT and *HLD, but the system makes them *RDY. Job logs are never spooled: PRTRPT RPT(*JOBLOG) prints one straight on paper.

Commands that answer with no message#

These succeed without a completion message: CHGJOB, HLDJOBSCDE, RLSJOBSCDE, HLDTRGEVT, RLSTRGEVT, SNDMSG, PRTTXT, CHGDEVSTS, CHGDEVFTR and CHGMCHSTS. Check the result with the matching Work with screen or RTV command if you need to.

Messages for things that aren't there#

  • Removing, holding or releasing a trigger that doesn't exist is ELC0103 (the value of TRG isn't valid).
  • Removing, holding or releasing a schedule entry that doesn't exist is ELC0302.
