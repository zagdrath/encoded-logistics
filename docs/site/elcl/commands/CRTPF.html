CRTPF

Command line and programs Firewall: None

Create Physical File

Syntax

CRTPF FILE(library/name) [SRCMBR(*FILE | library/name)] [TEXT(*SRCMBRTXT | *BLANK | text)]

The first 2 parameters can be given without their keyword, in that order: FILE, SRCMBR.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
FILEFileLibrary/name
prompter field 21 long; F4 lists files		Yes
SRCMBRSource memberLibrary/name
prompter field 21 long; F4 lists members		No*FILE*FILE
TEXTText 'description'Text
prompter field 50 long		No*SRCMBRTXT*SRCMBRTXT, *BLANK

CRTPF compiles a PF source member (a file definition, see Defining a file) and makes the physical file from it, with no records. Option 14=Compile on a PF member in Work with Members runs it for you, and F6 on Work with Files prompts it.

  • FILE is the file to make. Without a library it goes in your current library. A file of that name there already is ELC0204: to remake a file from a changed definition and keep its records, use CHGPF.
  • SRCMBR(*FILE), the default, compiles the member of the same name in the file's library. Name another member as LIB/MEMBER (SRCMBR(ELSYS/ITEMHIST)). A member that isn't there is ELC0202; one that isn't of type PF is ELC2247.
  • TEXT(*SRCMBRTXT), the default, takes the member's text, or, if it has none, the TEXT on the record format's R line. *BLANK leaves the file without text.

The listing always goes to Work with Output (WRKSPLF): a spooled file named after the file, in your interactive job, with the source and its sequence numbers, the record format (fields, record length, key) and each message. Then:

  • ELC2230: the file is made.
  • ELC2239: the definition has errors, and there's no file. Its messages are in the listing.

Making a file needs *CHANGE on the library (ELC0401); nothing can be made in ELSYS (ELC0205). An invalid file name is ELC0103.

CRTPF FILE(ELGPL/ITEMHIST) SRCMBR(ELSYS/ITEMHIST) TEXT('Item count history')
MONMSG MSGID(ELC0204)   /* there already: its records stay */
