WRKACL

Command line only Firewall: None

Work with ACLs

Syntax

WRKACL RTR(device name) ACL(name (up to 10 characters))

The first 2 parameters can be given without their keyword, in that order: RTR, ACL.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
RTRRouterDevice name
prompter field 10 long; F4 lists devices		Yes
ACLACLName (up to 10 characters)
prompter field 10 long		Yes

WRKACL opens Work with ACLs on one of a Router's access control lists: its rules in the order they're looked at, each with its sequence number, what it matches, its direction, permit or deny, its rate or quota, how many times it matched (hits) and when it last did. The default (*DFT) comes last. You type it at a command line; it doesn't run in a program.

How the rules work: the first rule that matches a resource (an item, a #tag, *ITEM, *FLUID, *PRES, *ENERGY or *ANY) going its way (*IN to the Router's network, *OUT from it, *BOTH) permits or denies it, up to its rate (a minute) or quota (a game day); past those it denies until the window turns. What no rule matches gets the default, set by rack.aclDefaultPermit (default true).

  • RTR is the Router's device name: ELC2601 if it isn't a Router on your network. ACL is the list's name on that Router: ELC2606 if it has none of that name.
OptionWhat it does
2=ChangePrompts CHGACLE with the rule's values.
4=RemoveRemoves the rule (RMVACLE), after you confirm.
6=Move up, 7=Move downMoves the rule one place (CHGACLE MOVE(*UP) or MOVE(*DOWN)).

F6 adds a rule (ADDACLE). Changing rules needs the Firewall's build permission, as those commands do. See Routers and Screens.
