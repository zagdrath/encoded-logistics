CLOF

Programs only Firewall: None

Close File

Syntax

CLOF [OPNID(*NONE | name (up to 10 characters))]

The first parameter can be given without its keyword, in that order: OPNID.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
OPNIDOpen file identifierName (up to 10 characters)
prompter field 10 long		No*NONE*NONE

CLOF forgets where a program has got to in a declared file: the next RCVF reads it again from the first record, and there's no record last read for UPDRCD or DLTRCD (ELC2204). It sends no message.

The file stays declared, so you can go on using it after CLOF: there's nothing to open again. You don't need CLOF at the end of a program, and nothing is held open between file operations (each one opens the file as it is at that moment). For reading, CLOF does the same as POSDBF POSITION(*START).

PGM
  DCLF FILE(ELSYS/JOBS)
  DCL  VAR(&N) TYPE(*INT)
  RCVF
  MONMSG MSGID(ELC2201) EXEC(SNDPGMMSG MSG('No jobs'))
  CLOF
  /* Read again from the top */
  DOWHILE COND('1')
    RCVF
    MONMSG MSGID(ELC2201) EXEC(LEAVE)
    CHGVAR VAR(&N) VALUE(&N + 1)
  ENDDO
  SNDPGMMSG MSG(%CHAR(&N) *BCAT 'jobs')
ENDPGM
