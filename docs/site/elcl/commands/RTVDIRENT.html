RTVDIRENT

Command line and programs Firewall: VIEW

Retrieve Directory Entry

Syntax

RTVDIRENT NAME(text) [RTNTYPE(*CHAR variable)] [RTNNETWORK(*CHAR variable)] [RTNHOPS(*INT variable)]

The first parameter can be given without its keyword, in that order: NAME.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
NAMEQualified nameText
prompter field 24 long		Yes
RTNTYPEReturn device typeA *CHAR variable the command setsNo
RTNNETWORKReturn networkA *CHAR variable the command setsNo
RTNHOPSReturn hopsA *INT variable the command setsNo

Looks up a qualified device name, SYSNAME/DEVICE, the way any command that's given one does: ELNET02/UPS01 is the device UPS01 on the network whose system name is ELNET02. Use it to check that a name works, and from where, before your program relies on it. See Exchange Switch and Directory Server.

A name on your own network (your own SYSNAME before the slash) resolves to that device directly, with 0 hops. For another network, every one of these has to hold, or the lookup fails:

  1. One of your network's Routers has a route to that network (ELC2603 otherwise).
  2. The device is published by a Directory Server on that network (CHGDIRENT, or WRKDIR's 2=Publish), and it's there (ELC2603 otherwise: an unpublished device looks just like a missing one).
  3. A Router on your network has a Control route to that network that's reachable now, and the ACL on that route, if it has one, lets the control request out (*CONTROL and *ANY rules; see ADDACLE). Otherwise ELC2604.
  4. You have the Firewall's view permission on that network (ELC2604 otherwise). A command that changes something checks its own permission there instead: CHGRSOUT on ELNET02/CTLIF01 needs build.

A name without a slash is ELC2603.

VariableGets
RTNTYPEThe device's type code (UPS, CTLIF...)
RTNNETWORKThe system name of its network
RTNHOPSRouter hops to that network (0 on your own)

A remote answer is kept for rack.directoryCacheSeconds (default 30) seconds (less if routes or networks change). An answer from that cache sends the warning ELC2608; the publishing, the control route and your permission are checked again even then. Every lookup goes into your Directory Servers' list of recent lookups, and a successful one counts towards the device's lookups on the other side. There's no other completion message.

DCL VAR(&TYPE) TYPE(*CHAR) LEN(10)
DCL VAR(&HOPS) TYPE(*INT)
RTVDIRENT NAME('ELNET02/CTLIF01') RTNTYPE(&TYPE) RTNHOPS(&HOPS)
MONMSG MSGID(ELC2603 ELC2604) EXEC(RETURN)
CHGRSOUT DEV(ELNET02/CTLIF01) SIDE(*UP) LVL(15)
