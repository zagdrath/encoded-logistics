CHGDEVFTR

Command line and programs Firewall: BUILD

Change Device Filter

Syntax

CHGDEVFTR DEV(device name) ACTION(*ADD | *RMV | *CLR) [ITEM(item id)]

The first 2 parameters can be given without their keyword, in that order: DEV, ACTION.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
DEVDeviceDevice name
prompter field 10 long; F4 lists devices		Yes
ACTIONActionSpecial valueYes*ADD, *RMV, *CLR
ITEMItemItem ID
prompter field 64 long; F4 lists items		No

Changes the item filter of an Ingress or Egress Port (wireless ones too), an Inventory Tap or a Collector or Deployer Plane: the nine entries you'd otherwise set in the part's screen. Any other device is ELC1303.

ACTIONWhat it does
*ADDPuts the item in the first empty entry. An item already there is left as it is. With no empty entry: ELC1305.
*RMVEmpties every entry holding the item. An item that isn't there changes nothing.
*CLREmpties all nine entries. ITEM isn't needed (and is ignored).

*ADD and *RMV need ITEM: leaving it out is ELC0102, from the compiler in a program. ITEM takes the item ID forms RTVITMCNT describes (an ambiguous bare name is ELC1205); the command handles items only.

Only the entries change. Whether the list allows or denies, tag and component matching (with a Filter Module) and fuzzy matching (with a Fuzzy Match Module) stay as they're set in the part's screen. See Cable parts.

The command sends no completion message.

CHGDEVFTR DEV(EGRESS01) ACTION(*CLR)
CHGDEVFTR DEV(EGRESS01) ACTION(*ADD) ITEM(COAL)
CHGDEVFTR DEV(EGRESS01) ACTION(*ADD) ITEM(CHARCOAL)
CHGDEVFTR DEV(TAP01) ACTION(*RMV) ITEM('minecraft:cobblestone')

Devices

RTVDEVSTS RTVDEVLST CHGDEVSTS RNMDEV RTVLANES
