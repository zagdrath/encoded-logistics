SNDDSPIMG

Command line and programs Firewall: None

Send Display Image

Syntax

SNDDSPIMG DEV(device name) RGN(name (up to 10 characters)) FILE(text) [SCALE(*DITHER | *NEAREST)] [COLORS(*DFT | *FULL | text)]

The first 3 parameters can be given without their keyword, in that order: DEV, RGN, FILE.

Parameters

prompter field 10 long; F4 lists devices		Yes
RGNRegionName (up to 10 characters)
prompter field 10 long		Yes

SNDDSPIMG shows a PNG picture in a region of a Display Panel screen, stretched to fill the region. It replaces whatever the region showed. A Text screen given an image becomes a Dashboard. The region must exist (CHGDSPRGN; on a screen with none set up, A is the whole screen), or it's ELC1314.

The file#

FILE is a PNG in the system's images folder, <world>/encodedlogistics/images/<SYSNAME>/ (see Folders on disk). Quote it: FILE('logo.png'). The name may use letters, digits, _, . and - (no spaces) and must end .png; its case doesn't have to match.

ProblemMessage
Images are off on this server: rack.allowImages (default AUTO) (AUTO is on in single-player, off on dedicated servers)ELC1315
No such file, a name it won't take, or not a PNGELC1312
Larger than rack.displayMaxImageBytes (default 4) MB, wider or taller than rack.displayMaxImageSize (default 4096) pixels, or more than rack.displayMaxImagePixels (default 16,777,216) pixels in allELC1313

The limits are read from the file's size and its header before any pixels are decoded. The picture is then drawn at the region's size away from the server's main thread, and shows when it's ready; players are sent the drawn region, never the file. If the region changes size, or the world is loaded again, it's drawn again from the file; a file that has gone, or grown past the limits, leaves the region blank.

Scaling and colours#

SCALEDoes
*DITHER (default)Smooth scaling, then a stable ordered dither into the colour mode's palette
*NEARESTNearest-pixel scaling and no dither: keeps pixel art crisp
COLORSPalette
*DFT (default)The same as 256
16The fixed 16-colour panel palette
64, 256A palette picked for the image
*FULLFull 24-bit colour, never dithered

Any other COLORS value is ELC0003. rack.displayImageColors (default 256) is the most colours the server allows: asking for more sends the diagnostic ELC1317 (severity 10) and shows the image at the limit, so the command still works. That diagnostic is the only message SNDDSPIMG sends when it succeeds.

The screen doesn't have to be online. A DEV that isn't on the network is ELC1301, and a device that isn't a Display Panel screen ELC1303.

Examples#

SNDDSPIMG DEV(DSP01) RGN(A) FILE('logo.png')
SNDDSPIMG DEV(DSP01) RGN(B) FILE('floorplan.png') SCALE(*NEAREST) COLORS(16)
SNDDSPIMG DEV(DSP02) RGN(A) FILE('photo.png') COLORS(*FULL)

See Images.
