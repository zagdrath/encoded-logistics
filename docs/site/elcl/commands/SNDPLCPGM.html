SNDPLCPGM

Command line and programs Firewall: BUILD

Send PLC Program

Syntax

SNDPLCPGM PGM(library/name) DEV(device name) [RUN(*NO | *YES)]

The first 2 parameters can be given without their keyword, in that order: PGM, DEV.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
PGMProgramLibrary/name
prompter field 21 long; F4 lists programs		Yes
DEVPLCDevice name
prompter field 10 long; F4 lists devices		Yes
RUNRun after loadingSpecial valueNo*YES*NO, *YES

Loads a program from a library into a Programmable Logic Controller on your network, the way you'd otherwise load it from a cartridge or the PLC's editor. Only a program compiled for a PLC, with CRTELPGM TGT(*PLC), can be loaded; any other is ELC1504. See Programmable Logic Controller and Redstone, PLCs and signals from ELCL.

  • PGM: LIB/NAME, or a bare name found down your library list (*LIBL; ELC0203 when no library on it has the program). *CURLIB/NAME is your current library.
  • DEV: the PLC's device name. ELC1301 for no such device, ELC1303 for one that isn't a PLC.
  • RUN(*YES) (the default) starts the program from the top once it's in; RUN(*NO) leaves the PLC stopped, ready for STRPLC.

Loading stops the PLC first, which sets its outputs to 0, and clears its log and any fault. You become the program's loader: when the PLC is on a network, its program's commands run with your Firewall permissions. Loading the same program (by name) again keeps its RETAIN variables; a different program starts without them.

On success the command sends ELC1509.

SNDPLCPGM PGM(PLCLIB/PUMPCTL) DEV(PLC01)
SNDPLCPGM PGM(LAMPTEST) DEV(PLC02) RUN(*NO)

PLCs

RTVSNSVAL STRPLC ENDPLC
