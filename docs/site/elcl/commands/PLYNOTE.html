PLYNOTE

Command line and programs Firewall: BUILD

Play Note

Syntax

PLYNOTE DEV(*ALL | device name) [INST(*HARP | *BASS | *SNARE | *HAT | *BASSDRUM | *BELL | *FLUTE | *CHIME | *GUITAR | *XYLOPHONE | *IRONXYLO | *COWBELL | *DIDGERIDOO | *BIT | *BANJO | *PLING)] NOTE(whole number)

The first 3 parameters can be given without their keyword, in that order: DEV, INST, NOTE.

PLYNOTE makes Speakers play a note block note: the instrument INST at pitch NOTE, 0-24 (two octaves, as a note block's 25 pitches; 12 is the middle one). A note outside 0-24 stops the command with ELC2407 before any speaker plays.

The instruments are the note block's 16, by their sounds rather than the block under them:

A sequence#

Give NOTE a list (up to 32) and the speaker keeps it as a sequence: the first note plays now, and each rising redstone edge at the speaker plays the next, starting over after the last. That needs the speaker's Trigger to include redstone; a speaker set to Network plays only the first note. Another PLYNOTE starts a new sequence from its first note.

The instrument and notes become the speaker's settings, like a source chosen on its settings screen, so a single note is played again on each rising redstone edge too.

DEV takes up to 32 names, or *ALL for every online Speaker on the network that takes network commands. Every named speaker is checked first: not there (ELC1301), offline (ELC1302), not a Speaker (ELC1303), or its Trigger is Redstone (ELC2408; *ALL leaves those out). It sends no completion message.

Examples#

PLYNOTE DEV(SPK01) INST(*BELL) NOTE(18)
PLYNOTE DEV(*ALL) INST(*PLING) NOTE(6 10 13 18)   /* one note a redstone pulse */

A note sounds at once and rings out on its own, so a program that wants a tune plays notes with a DLYTICK between them, or uses a MIDI file with PLYMID.
