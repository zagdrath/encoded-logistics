CHGPF

Command line and programs Firewall: None

Change Physical File

Syntax

CHGPF FILE(library/name) [SRCMBR(*FILE | library/name)] [TEXT(*SAME | *BLANK | text)]

The first 2 parameters can be given without their keyword, in that order: FILE, SRCMBR.

Parameters

KeywordPromptTakesRequiredDefaultSpecial values
FILEFileLibrary/name
prompter field 21 long; F4 lists files		Yes
SRCMBRSource memberLibrary/name
prompter field 21 long; F4 lists members		No*FILE*FILE
TEXTText 'description'Text
prompter field 50 long		No*SAME*SAME, *BLANK

CHGPF makes a physical file again from its definition, keeping its records. Change the file's PF member (add a field, lengthen one, change the key), then run CHGPF. Option 14=Compile on a PF member whose file exists already runs it for you; Work with Members and Work with Files show * in Chg while a file's definition has changed since it was made.

  • FILE must exist. Without a library it's looked for down your library list.
  • SRCMBR(*FILE), the default, uses the member the file was made from. Name another (LIB/MEMBER) to make the file from that one instead; it becomes the file's member from then on. A file made by RUNQRY OUTPUT(*OUTFILE) or CPYF CRTFILE(*YES) has no member, so it needs SRCMBR, else ELC2247.
  • TEXT(*SAME), the default, keeps the file's text; *BLANK clears it.

What happens to the records. Each record keeps its relative record number and its value in every field whose name and type are both still there. A text field made shorter is cut. A field gone, or of another type now, loses its values: CHGPF sends ELC2232 (a warning) for each. New fields start blank. Then ELC2231 says how many records were kept.

When nothing changes:

MessageWhy
ELC2246The definition has errors (see its listing in Work with Output).
ELC2209A record's value no longer fits its field (a number with more digits than the field takes now).
ELC2203The key is UNIQUE now, and two records have the same key.
ELC0207The records would take more storage than the drives have left.

The listing goes to Work with Output as CRTPF's does, with a line for each field dropped. Changing a file needs *CHANGE on its library (ELC0401); ELSYS files can't be changed (ELC0205).

Compile the programs that use it again

A program keeps the record format it was compiled with. If CHGPF drops or retypes a field the program declares, its file operations fail with ELC2207 until you compile it again.

CHGPF FILE(ELGPL/ITEMHIST)
CHGPF FILE(ELGPL/ITEMHIST) SRCMBR(ZAGLIB/ITEMHIST2) TEXT('Item counts, with mod')
