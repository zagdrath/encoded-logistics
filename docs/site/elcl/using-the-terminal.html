Using the terminal

The green screen's layout, the keys and the mouse, the command line, the F4 prompter, F1 help windows and phosphor colours.

On this page
  1. Screen layout
  2. Keys
  3. Mouse
  4. The command line
  5. The prompter (F4)
  6. Help windows (F1)
  7. Phosphor colours

Every Terminal OS screen works the same way: a header, a body, a command line, a message line and a row of function keys. Learn them once and every screen follows. This page covers the screen itself; Screens goes through the screens one by one.

Screen layout#

Every green screen (the Terminal Desk, the Integrated Midrange System's console, and the machines: the Midrange control panels, Card Punch, Card Reader, Line Printer, Disk and Tape Drives, PLCs) sits in the same panel as the mod's other machine GUIs: the block's name at the top, and the 80 by 24 screen in a recessed well below it, one screen pixel to a GUI pixel, crisp, with a 6-pixel margin of the screen's background round the text. The panel is drawn at the largest whole scale that keeps it within about 60% of the window's width and 70% of its height, centred. The game's HUD (crosshair, hotbar, health and the rest) is hidden while it's open. The screen stays blank for a moment when it opens, until the system's details arrive from the server.

RowWhat's there
0The screen's id at the left (MAIN, WRKLIB...), its title centred and bright, and System: and the system's name (the SYSNAME system value) at the right; *OFFLINE without a network.
1The game clock at the right: Day 2 07:14:22 (the game day, and the time of day with day start at 06:00).
2–19The screen's body. Lists show More... or Bottom on row 20 at the right; the Main Menu on row 18.
20The prompt over the command line: Selection or command on menus, Parameters or command on lists.
21The command line, ===> and a 72-character field (it holds up to 216 characters, scrolling as you type). Screens without a command line (the prompter, displays, Sign On) leave it out. Command Entry has a three-row command line on rows 19–21, under its prompt Type command, press Enter. on row 18.
22The message line (bright). MW (messages waiting) appears at its right end, column 76, while you have unread messages in your queue; it goes once you display them.
23The function keys this screen takes, bright. Clicking a key's label presses it.

Input fields are bright and underlined. Pop-up windows (help, confirmations, value lists, small forms) are drawn in a box over the screen; while one is open only its fields take the cursor.

Keys#

Function keys act when the key is released. Shift adds 12 to F1–F12, so F13 is Shift+F1 and F24 is Shift+F12; real F13–F24 keys work too. While the terminal is open, the game's fullscreen and screenshot bindings are switched off if they're bound to function keys, and given back when it closes.

KeyWhat it does
EnterIf the command line has text: a menu option number on a menu, an editor command in the editor, otherwise the text runs as a command. If it's empty: the screen's own action (take the options typed in a list, apply the editor's line commands, sign on...). In a window, the window's action.
EscCloses the top window, else goes back one screen. On the Main Menu or Sign On it closes the terminal.
F1 HelpHelp for the field the cursor is in, or for the screen, in a window. See help windows.
F3 ExitCloses the terminal from most screens. In the prompter it returns without the command; in the editor it leaves the editor (asking to save if there are changes); in a window it closes the window.
F4 PromptOn the command line with a command typed: opens the prompter for it. On a prompter field: its value list, or the nested command's prompter. On an editor source line: prompts that statement. Elsewhere: a hint for the field on the message line.
F5 RefreshClears the message line and fetches the screen's data again (on the prompter: resets the values to their defaults; in Update Data's entry mode: clears the fields).

On Work with Inventory it opens Deposit Items (and there deposits everything); in Update Data it starts entry mode.

Work with Exchange: requests only. Update Data: delete the record. In the End confirmation of Work with Active Jobs: end immediately. In the editor's exit confirmation: exit without saving.

F15Editor: column ruler on or off.
F16 / F17Editor: repeat the last FIND / the last CHANGE.

Not every screen takes every key: row 23 lists the ones it does. On Sign On, F9 and F24 do nothing. Only printable ASCII characters (space to ~) can be typed. Some fields fold letters to upper case (names) or take only digits, signs, a decimal point and commas (numbers).

Mouse#

  • Clicking a function key's label on row 23 presses that key.
  • Clicking a field puts the cursor there.
  • Menus (Main Menu, Work with Job): clicking an option types its number on the command line; double-clicking goes there.
  • Lists: clicking a row types the screen's default option in its Opt column; double-clicking does it.
  • The wheel rolls like Page Up / Page Down.

The command line#

Every screen with ===> takes commands. What you type is handled in this order:

  1. On a menu, a number is the menu option (one that isn't there says Option N is not on this menu.). In the editor, editor commands (FIND, SAVE...) come first.
  2. clear (any case) clears Command Entry's history (Command history cleared.).
  3. A command that opens a screen (WRKLIB, WRKMBR LIB(ZAGLIB), DSPMSG, GO MAIN, SIGNOFF...; see Screens) is checked against its definition and opens the screen on this desk.
  4. Anything else goes to the server and runs as an ELCL command in your interactive job.

An ELCL command on the command line is parsed, checked that it may run there (ELC0106 for a statement only a program can use), checked against its definition and for Firewall authority, then run. Its messages are shown as ID text (escape and completion messages bright), the values of any RTN* parameters are listed as RTNLVL = 7, and the last message goes to the message line. If the command produced output and you're not on Command Entry, Command Entry opens to show it. The command and its messages also go in your interactive job's log (screen commands, which are handled at the desk, don't).

CALL on the command line starts the program in your interactive job and answers at once (ELC0108, Program LIB/NAME running in job ...); its messages come to Command Entry when it ends. DLYJOB typed on a command line has nothing to hold up and completes at once.

There are no variables on the command line (an &name is ELC0002), but expressions of literals work, for example SNDMSG MSG('Shift' *BCAT 'change'). RTN* parameters are optional on the command line even when a program would have to give them. Language statements such as DCL, IF or CHGVAR answer ELC0106 there. A CHGSYSVAL typed at a desk takes effect on that desk at once (the header's SYSNAME, PHOSPHOR, SECLVL); other desks pick it up when they're next opened.

Tab completion (Command Entry only) completes the first word from the ELCL command names and later words from the network's item names. One match fills in the word; several are listed on the message line.

The prompter (F4)#

Type a command name (with or without some parameters) on a command line and press F4. The prompter shows one row per parameter, built from the command's definition: the same parameters its page in the command reference lists.

  • The title is the command's description and name. Each row has the label with dot leaders (bright when the parameter is required), the keyword (dim), the input field (the parameter's length, at most 24 shown; longer values scroll) and a hint (dim) such as 1-999999, *FAIL, *PARTIAL, Name, F4 for list or *CHAR variable. A long hint wraps onto the next row.
  • Required parameters come first. The others sit under Additional Parameters, shown with F10 or as soon as any of them has a value.
  • A list parameter (hint + for more values) takes several values separated by blanks; typing just + and pressing Enter opens a window with four value fields. Values that go together can be grouped in brackets, as PLYMID MAP((1 SPK01) (10 SPK04)): a group's values count as if listed one by one.
  • F4 on a field opens its value list, Select Value - label: special values first, then what the server lists for that kind of parameter. Items in the network match what's typed in the field by name or id, sorted by name, up to 200; there are lists of devices, libraries, jobs and system values, and of members, programs and files (from the library typed in the field, or down your library list). Type 1 next to one and press Enter (or double-click it). On a field with no list, F4 shows its hint on the message line. On a command parameter (SBMJOB CMD, ADDJOBSCDE CMD, or IF THEN in the editor) F4 opens the prompter for the nested command instead.
  • Enter checks the values: a missing required value (ELC0102), a value not valid for a parameter (ELC0103) or out of range (ELC0004) is shown on the message line and the cursor goes to that field. When it's clean the prompter builds the command (keywords in order, values left at their defaults left out, text quoted where needed).
  • From Command Entry, the built command is put back on the command line for you to press Enter. From any other screen's command line it runs straight away. From the editor it replaces the statement in the source.
  • F5 resets every value to its default. F3 and F12 return without a command. F1 on a field explains that parameter: what it takes, its special values, its default and whether it's required; F1 elsewhere lists all the command's parameters (required ones marked *).

Help windows (F1)#

F1 opens a window titled Screen title - Help over the current screen with help for the field under the cursor, or the screen's help if the field has none. In lists, the Opt column has its own help listing the options. In the prompter, help comes from the command's definition. GO HELP on a command line opens the same window. The window's keys are F3=Exit help F12=Cancel; Page Up / Page Down scroll it (More... and Bottom say where you are). A screen without help text says No help is available for this screen. Press F12 to return.

The screen help on Screens follows these texts.

Phosphor colours#

The screen can be drawn in green, amber or white phosphor. Each player chooses on More Keys and Settings (F24): Green, Amber, White or *SYSVAL (type the word, its start, or 1–4). The choice is kept in the client config as terminal.phosphor (default *SYSVAL). *SYSVAL follows the system value PHOSPHOR (*GREEN, *AMBER or *WHITE; default *GREEN), so a server admin can set every terminal's colour on a system at once. A change made at a desk takes effect on that desk straight away.
