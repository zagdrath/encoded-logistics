ENCODED LOGISTICS - HANDOFF: MIDRANGE LINE v4 (fixes + Disk Drive + Tape Drive)
===============================================================================
This package is complete: it supersedes the v3 package (use only this one). It contains every Midrange-line block with all
fixes. Changes since v3:
  - High-res cut down: every texture is 1 texel per model px except the segment-display inserts and the Integrated's console
    screen (section 1). The old 4-texel panel sheets (panels*.png) are gone - delete them from the repo if v3 was applied.
  - 1311 Disk Drive: the whole upper front is one slope (a solid box rotated 22.5 about X, no gaps or see-through), a 3D
    glass compartment with the disk pack inside (translucent glass model).
  - NEW Printout item (section 9): the Line Printer prints Printouts - continuous-form green-bar paper - instead of
    Written Books.
  - 729 Tape Drive: 18 x 40 x 14 px, centred, 2.5 blocks tall (1 x 3 footprint, master + middle + top parts), a real reel
    window with 3D reels behind translucent glass.
Updates the Midrange line already in the repo (commit 4b74166 added its blocks). Fixes the in-game issues found:
texture clipping and see-through faces, models split between two blocks, GUIs with buttons and slot grids, the Integrated
console not opening the Terminal OS. Adds a 1311-style Disk Drive and a 729-style Tape Drive (+ Tape Reel item).
Paths relative to the repo root; the zip mirrors them under src/. REPLACE the Midrange line's models, blockstates and
textures with these (keypunch, card_reader, line_printer, midrange_system, expansion_cabinet, integrated_midrange).

=====================================================================================================
1. ART RULES (applied to every block here)
=====================================================================================================
  - Scale unchanged (1 model px = 6.25 cm). EVERYTHING is 1 texel per model px (Minecraft-size pixels): cabinets, panels,
    lamps, buttons, slots, latches, louvres, the printer's control strip, windows. High-res (4 texels per px) is used ONLY
    where 1:1 cannot carry the content: the segment displays (tiny emissive inserts covering just the display: Midrange 3 x
    1.25 px, Integrated 3 x 1.25 px) and the Integrated's console screen (the Terminal Desk's crt_screen_* textures).
    Detail that needs more than 1:1 is modelled in 3D instead (the 1311's disk pack, the 729's reels).
  - docs/TEXTURE_STYLE.md method: material ramps (cream, IBM door blue, steel) - flat fields with stepped falloff from the
    top-left in whole ramp steps, structural seams and louvres, no grain, no specks.
  - No clipping: no overlay plates on top of faces. Every housing's front face carries its own panel texture; the only
    overlays are emissive (lamps, displays, screens), 0.01 px in front of a face and never crossing another element.
    No coplanar faces between elements (top housings sit ON the body, deck elements have no down faces).
  - Centred on the block: every model is centred on its master block's centre (x = 8) and flush to the back (z = 16).
    Overhang of up to 2 px past the block's sides is allowed and is NOT collided (collision/selection = the model's boxes
    clipped to the footprint's blocks - shapes/collision_shapes.json). Wider models get dummy blocks on BOTH sides.

3. INTERACTION AND GUIS (Terminal OS style - text only)
=====================================================================================================
All Midrange-line GUIs are CRT text screens on the existing Terminal OS renderer (CrtScreen panels): option fields,
F-keys, the command line, the message line - NO buttons, NO item slots, NO player inventory grid, and the vanilla hotbar /
HUD is hidden while one is open (skip rendering the gui hotbar while a CrtScreen is the current screen).
Items go in and out physically: use a Diskette on the Midrange's drive slot (or a Diskette Magazine on the Integrated's
magazine unit), cards on the Keypunch / Card Reader hopper, paper on the Line Printer, a Storage Drive on the Disk Drive, a
Tape Reel on the Tape Drive; sneak-use with an empty hand ejects (or option 4 on the screen, which drops it at the player).
Screens (grids in layouts/*.txt, renders previews/crt_*.png):
  MRCTL  Midrange Control Panel - status line; diskette drives list (4=Eject 5=Display recipes 8=Make default library); job
         list (3=Hold 4=End 6=Release); F7=IPL F10=Hold queue F11=Release.
  IMCTL  Integrated System Control Panel - the same with the magazine's 4 positions (4=Remove from magazine) and 4 threads.
  CARDPUNCH - 3 x 3 item-name fields (F4 = item list prompter), result line, blank / punched card counts, card image; F6=Punch.
  CARDRDR - the deck in the hopper (recipe per card, new / replaces), the diskette before -> after; F6=Read.
  PRINTER - report field 1-4 (4 = ELCL spooled file + name / *LAST, F4 list), pages, paper loaded; F6=Print.
  DSKDRV - Disk Drive: pack (storage drive) type, capacity, types; 4=Unload (spins down first) 5=Display contents.
  TAPDRV - Tape Drive: reel volume, used, last access; 4=Unload (rewinds first) 5=Display contents 7=Rewind.
Integrated click zones (by the hit position against the model boxes, not by footprint block):
  console = console_hood + console_keyboard -> opens the Terminal OS (as a Terminal Desk: same session and sign-on);
  control panel = body_left + magazine_unit -> IMCTL; body_right / plinth -> nothing (no GUI).

=====================================================================================================
4. NETWORK ROLE - both Midrange systems are NETWORK CONTROLLERS
=====================================================================================================
A Midrange System or Integrated Midrange System is the root of its network (like the 2U / 4U rack controllers): it is a
lane source and holds the network's energy buffer. Proposal: Midrange System = a 1-block controller (lanes 4 x
lanes.perControllerFace = 128, energy 4 x energyPerBlock = 100,000 FE); Integrated = the 2U rack controller (192 lanes,
500,000 FE). Same rules as the rack controllers: one controller system per network - a Midrange with a block controller, a
rack controller or another Midrange on one network -> "Controller conflict" on all of them; no redundant pairs. Everything
else (job host, scheduler, diskettes) unchanged.

=====================================================================================================
5. STORAGE: DISK DRIVE AND TAPE DRIVE
=====================================================================================================
  disk_drive - holds ONE Storage Drive item (any tier) and serves it as hot storage exactly like a Drive Bay slot
    (same capacity, priority, fullness rules); 1 lane; spin-up 40 ticks after insertion before it's readable (window_spin);
    4=Unload / sneak-use spins down (20 ticks) then ejects. Device type DISK, names DISK01...
  tape_drive - holds ONE Tape Reel (NEW item, 65,536 items, 1,024 types [config]) as COLD storage in the same tier as the Tape
    Libraries (archive / recall rules of the tape-library handoff; this is one drive with one reel, no picker): load 100 ticks,
    read/write 3 s + 1 s per 4K items; reels turn while reading/writing. 1 lane. Device type TAPE, names TAPE01...
  tape_reel - item; tooltip "n / 65,536 items"; contents kept in a data component (like LTO tapes).

9. PRINTOUT (new item - the Line Printer's output, replaces Written Books)
=====================================================================================================
Item encodedlogistics:printout, stack size 1. Component encodedlogistics:printout {title, report (inventory | joblog | devices |
splf:<name>), system, printed (game day + time), printer (device name), pages: list of pages, each up to 48 lines of up to 56
characters + an ink per line (normal | light | red)}. Icon: textures/item/printout.png (1 page) or printout_stack.png (fan-fold
stack, 2+ pages) via items/printout.json (range_dispatch on the page count). Tooltip: title, pages, "Printed on PRINTER01, Day 2
14:32".
Page format (tools/printout.py is the reference renderer - render it exactly so): a 384 x 512 canvas = textures/printout/paper.png
(green bars 3 lines tall every 6 lines, 24 px tractor strips with sprocket holes every 16 px, perforations) + text in the
terminal font sheet (textures/font/terminal.png, 6 x 10 cells, drawn glyph by glyph - NOT the MC font) at x 32 + col * 6,
y 16 + row * 10: 56 columns x 48 rows. Row 0: system (left), title (centred), date (right); row 1: "ENCODED LOGISTICS" + "PAGE n
OF m" (light ink); row 2: a rule (box glyph U+2500, light); body from row 4; row 47: "*** END OF REPORT ***" on the last page,
else "*** CONTINUED ***" (light). Inks: normal 2C3036, light 5A606A, red 9E2A22 (alerts: low stock, held jobs).
Rendering:
  - Held: like a filled map - first person (one or both hands), the page fills the view (ItemInHandRenderer map path with a
    dynamic texture of the current page, cached per item stack + page). Previews: previews/printout_in_hand.png.
  - Item frame: the first page on the frame, like a map.
  - Use (right-click): a reader screen in the game's GUI kit: dark panel, title (TEXT), the page at the largest integer scale
    that fits, page arrows (terminal/button) and "Page n of m"; PageUp/PageDown and the scroll wheel turn pages; Esc closes.
    previews/printout_reader.png.
Line Printer: each report becomes ONE printout item with all its pages (1 paper per page, as before; out of paper mid-report
-> the pages printed so far are output and the job waits with ELC1306). Reports format as in previews/printout_page_*.png:
  inventory: ITEM (30) QUANTITY (8, grouped) TIER (5) LOCATION; light ink for cold-tier rows; totals; red LOW STOCK lines;
  job log: TIME JOB EVENT, red for held / failed jobs; devices: NAME TYPE STATUS LANES LOCATION; spooled file: its lines as-is
  (cut at 56 columns, continued on the next line with a light ">").
Files: textures/printout/paper.png, textures/item/printout.png, printout_stack.png, models/item/printout*.json,
items/printout.json, lang keys in en_us.midrange_v3.json; tools/printout.py.
