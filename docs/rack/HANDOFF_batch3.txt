ENCODED LOGISTICS - HANDOFF: SERVER RACK DEVICES, BATCH 3 (Rack Console, Wireless Controller, Tape Libraries + tiering)
====================================================================================================================
Built on the implemented rack (repo 4212e5e: RackDeviceType with frames()/slots(), RackClientDevices panels +
RenderExtra, RackDeviceInfo popup, lane pools). Art follows the rack-device conventions: 8 texels/px sheets, smooth
shading, no flat fills, no speckle, unbranded. Previews were rendered from these files in the repo's rack.
Paths are relative to the repo root; the zip mirrors them under src/.

=====================================================================================================
1. API ADDITIONS
=====================================================================================================
1.1 6U devices. RackDeviceType allows 1..4 U; raise to 1..6. Sheet layout by size:
      size <= 4: 128x128 - front (0,0)-(104,8n), back (0,32)-(104,32+8n), chassis (112,0)-(128,16), extras (0,64)
      size 5-6 : 128x256 - front (0,0)-(104,8n), back (0,64)-(104,64+8n), chassis (112,0)-(128,16), extras (0,128)
    RackClientDevices.frontQuad/backQuad and the elevation must take the back origin (32 or 64) and the sheet height
    (128 or 256) from the type (add RackDeviceType#backOrigin() / #sheetHeight()). The 6U models' UVs are already
    computed for 128x256; its _on/_fault strips declare frame width/height 128x256 in their .mcmeta.
1.2 Animated multi-part devices. The Rack Console is drawn by a RenderExtra that submits its baked part models
    (drawer, keyboard, lid) with PoseStack transforms; the device keeps a client-side animation state (open progress,
    lid progress) synced from a server "open" flag. Register the part models as additional models.
1.3 Device interaction. RackDevice#use(player, hit) for right-clicking a unit with the front door open (the console
    uses it; others ignore it). The rack's existing raycast-to-U targeting supplies the device.
1.4 Cold storage tier (section 4) - a NetworkStorage flag isCold(), recall requests, and the terminal/plan hooks.

=====================================================================================================

Panel (gui/rack/wireless_controller.png, screens/rack/wireless_controller.json): linked terminals (head, player name,

HUD: Linked terminals; Connected (terminals open right now).

4.2 Items:

    models/item/<id>_3d.json).
4.3 TIERING RULES
  Tiers: HOT = Storage Drives in Drive Bays, NAS, SAN (instant). COLD = tapes in online Tape Libraries (slow).
  Every hot stack records its last-access game tick (insert, extract, craft use, terminal view does NOT count).
  ARCHIVING (each library, every 200 ticks, if it has an idle drive):
    candidates = hot item types whose last access is older than the library's age threshold,
      minus keep-hot filter matches, minus pinned items, minus anything a running crafting job has reserved;
    only if the free-space trigger is off, or hot storage is above its % threshold;
    oldest first: pick a tape with room (fullest-first to pack tapes), picker loads it into the drive, write time
    passes (OPEN 1), the stack moves from hot to the tape; the tape stays in the drive while more archiving is queued,
    then is returned to its slot.
  RECALL: a request for a cold item (terminal extract, Egress Port, crafting plan, any network extraction):
    1. the network serves what is hot first; the remainder becomes a recall on the library holding it (oldest tape
       request first; one tape per idle drive - parallel recalls = drives);
    2. picker -> load (load time) -> read time -> items go back to HOT storage (stamped as accessed now), then the
       original request completes from hot storage;
    3. if hot storage is full, recall what fits and report "Hot storage full" on the request.
  Pinned items are recalled automatically if found on tape; changing keep-hot/pinned never archives immediately.
  Libraries with no drive hold tapes but can't read or write them (their items show cold, recall reports "No drive").
4.4 TERMINAL INTEGRATION (screens/terminal/cold_items.json)
  - Cold items (any count on tape) list in every terminal with the tape badge (terminal/tape_badge, 7x5) at the slot's
    bottom-left (offset 0,11), above the item, below the count. Count = hot + cold.
  - Tooltip adds: (tooltip/tape icon) "On tape" (#7FB3F0) and "Recall in ~Ns" (estimated: queue + load + read);
    while recalling: "Recalling... N%".
  - Requesting a cold item shows the recall indicator on that slot: a progress bar along the slot bottom
    (terminal/recall_track + recall_fill, offset 0,14) and the animated spinner (terminal/recall_spinner, 4 frames,
    top-right); the items arrive when it completes (and drop to the cursor/inventory as a normal extract).
  - Craft Plan: cold ingredients count as Have, shown in light blue with the tape marker (rack/craft_plan_recall) in
    the Have column; the header shows "Recall +Ns" and the summary line "Includes tape recall: +Ns"; the job's ETA and
    Job Status include the recall. Starting the job starts the recalls immediately.
  Mockups: previews/terminal_cold_items.png, craft_plan_recall.png.

=====================================================================================================
8. OPEN QUESTIONS (proposals included)
=====================================================================================================
1. Timing: load 60 ticks (picker), read/write 2 s + 1 s per 4K items moved; newer generations are faster - each
   generation above LTO-6 cuts read/write time by 15% (LTO-10 ~ 0.52x).
2. Defaults: archive after 2 hours (game time) untouched; free-space trigger ON at 80% hot full.
3. Removing a library or pulling a tape: tapes keep their contents (data component) - a pulled tape or a broken
   library's tapes become an OFFLINE ARCHIVE (items vanish from terminals); re-inserting a tape into any library
   brings them back. Ejecting through the mail slot (operator button) is the friendly path. Nothing is ever deleted.
4. Several libraries on one network form one cold pool; archiving picks the library with the most free tape space,
   recall uses whichever library holds the item.
5. Wireless Controller: works across dimensions [config, default on]; more than one per network allowed (handhelds link
   to a specific controller; any online one on the network can serve it [config]).
6. Rack Console Fabrication mode: yes, as an option - a crafting-grid toggle in its screen once a Memory Die is applied
   to the console (shift-use), mirroring the Fabrication Terminal upgrade path.
