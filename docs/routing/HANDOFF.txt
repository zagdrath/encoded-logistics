ENCODED LOGISTICS - HANDOFF: ROUTING AND INTERCONNECT (dynamic routing, Internet Exchange, Router ACLs, VLAN trunking, Directory)
================================================================================================================================
TERMS
  - Reachability: which networks a Router can get traffic to, and by which path. Today only directly linked networks; after
    this, any network learned through routing.
  - Policies: the existing Router routes (Move or Share rules between two networks). They stay as they are, but may now target
    any reachable network, not only a neighbour.
  - Traffic for a policy follows the best current path, possibly crossing other networks.

1. DYNAMIC ROUTING (RouterDevice + a new network/routing package)
=====================================================================================================
  - routingMode: STATIC (default; every existing Router loads as STATIC, and its routes behave exactly as today) | DYNAMIC.
  - Adjacency: two DYNAMIC Routers whose networks are directly linked (Network Bridge, Wireless Bridge, Point-to-Point Link, a
    Linked entry, or a shared Exchange Switch) exchange HELLO every 20 ticks; 3 missed -> neighbour down. State per neighbour:
    INIT -> FULL (link-state databases synced) / DOWN.
  - Link-state: each Router floods an LSA (its networks, its neighbours with costs, transit policy, sequence number) to its
    neighbours; every Router runs Dijkstra over the LSAs it holds (on change, debounced 20 ticks).
  - Cost of a hop = ROUTING_BASE_COST [100] x 1000 / (min(link lanes, router throughput) + 1), rounded, min 1 (Optical
    Transceivers raise throughput -> lower cost). Per-neighbour cost override (Router GUI / CHGNBR - see 6).
  - Route table entry: destination network, next hop (neighbour), total cost, hop count, source (*CONNECTED | *STATIC |
    *DYNAMIC), age. STATIC (today's Linked routes and manual entries) overrides DYNAMIC for the same destination.
  - Policies (existing routes) gain `dest` = any reachable network (a network id, not only a Linked index); legacy routes are
    migrated to the network id of their Linked entry and keep working unchanged.
  - Multi-hop: a policy to a non-adjacent network sends traffic hop by hop along the best path; each hop's Router forwards it
    (it never lands in an intermediate network's storage).
  - Transit (Router setting): NONE (default) | LISTED (networks) | ALL. A path may cross a network only if its Routers allow
    transit for the source network; transit throughput counts against each crossed Router.
  - Failover: on adjacency loss, recompute within reconvergeSeconds [config 5]; while a policy has no path its Move transfers
    and Share views PAUSE (queued, nothing lost) and resume on the new path.
  - Loops: maxHops [config 16]; split horizon (never advertise a route back to the neighbour it was learned from); LSA
    sequence numbers + age-out (60 s).
  - Throughput of a path = the minimum of every hop's Router throughput (and link lanes).
  - HUD + Router GUI: routing mode, neighbour count, route count.

3. ROUTER ACLs
=====================================================================================================
  Named ACLs per Router: ordered rules {seq, match (item | #tag | *ITEM *FLUID *PRES *ENERGY | *ANY), dir (*IN *OUT *BOTH),
  action (*PERMIT | *DENY), rate (per minute, optional), quota (per game day, optional), hits, lastMatched}. First match wins;
  default action [config aclDefault *PERMIT] shown as the last line. Applied to a policy, a neighbour or an exchange peer, in
  either / both directions. Applies to Move (denied items aren't moved) and Share (denied items are invisible to the other
  side). Rate / quota exceeded = deny until the window resets. Hit counters + last matched.
  GUI: the Router's ACLs tab (previews/gui_router_acls.png): ACL picker, rule list (#, match, action, hits - compact counts
  1.2k), Add / Edit / Del / Up / Dn (common/button_wide).

4. VLAN TRUNKING
=====================================================================================================
  Segment IDs 1-4094 alongside names; on first load existing segments get IDs in order (index 0 -> ID 1 = the default
  segment). Ports on L2 / L3 switches and on the new Trunk Port get a mode: ACCESS (one segment - today) | TRUNK (allowed
  segment list + a native segment for untagged traffic). A trunk's lanes are shared by its segments; QoS rules still apply.
  Isolation holds: segments on a trunk still can't see each other unless an L3 Switch or Router routes between them.
  trunk_port (cable part): models/part/trunk_port(_active).json = the ingress port's geometry with its own textures
  (textures/part/trunk_port/{front, side, status}.png; status: a static two-tone LED + up to 3 light-blue segment-count bars).
  Switch port GUI (previews/gui_switch_ports.png): port, mode, allowed, native (the switch panel's new Ports tab).

  Devices get a `published` setting (default false). Qualified names SYSNAME/DEVICE (e.g. ELNET15/LGT01): any ELCL command

  network AND a CONTROL policy (a new Router policy type beside MOVE and SHARE, with ACL support - its ACL matches *CONTROL).
  The caller needs the Firewall permission on the TARGET network; checks run on the target side. Cache 30 s [config],
  invalidated on route or device changes. GUI (previews/gui_directory.png): Published, Remote, Lookups.

8. MIGRATION
=====================================================================================================
  Routers load as STATIC; every Route keeps source / mode / filter / options; its dest index is resolved once to the Linked
  entry's network id (kept in sync). Segments get IDs 1..n in their current order; device segment indexes map to those IDs;
  every switch port loads as ACCESS on its current segment. Devices load unpublished. No ACL = today's behaviour.
