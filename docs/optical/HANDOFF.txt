1. FIBER SPAN LOSS
=====================================================================================================
  Only Fiber Cable runs: a continuous run longer than fiberSpanThreshold [config 256 cable blocks] loses 1 lane per further
  fiberSpanLossStep [32], down to 1. An Optical Amplifier in the run (block inline, or a rack Amplifier patched in) resets the
  count from that point. Config fiberSpanLoss [on]. Network / Dense Cables, Network / Wireless Bridges and P2P Links unchanged.
  HUD on a Fiber Cable (and the Cable Certifier if present): length since the last amplifier, lanes after loss.
  Computed per cable network on topology change (the run graph's longest unamplified path to each endpoint), cached.

=====================================================================================================
2. OPTICAL MULTIPLEXER - optical_multiplexer (block, 16 x 16 x 16) and optical_multiplexer_rack (1U)
=====================================================================================================
  8 channels; each assigned to a client network (a Link Card copied from any device on it) or a segment of its own network.
  Line port: a Fiber Cable run to a matching multiplexer, paired with a Link Card. Each channel up to 32 lanes; the line carries
  all channels (not one cable's 32); span loss applies per channel. Channels isolated like separate cables.
  Art: block - the guide's frame, 8 recessed channel-LED windows, recessed line in / out ports, raised slats on the sides; glow
  = 8 static two-tone channel LEDs in wavelength colours (dye bases: red, orange, yellow, lime, green, light blue, blue,
  purple). Rack - the Monitoring Server sheet, yellow type tab, 8 channel LED sockets, two Router sockets (line in / out);
  _on: the 8 channel LEDs (a down channel blinks), status LED; _fault: line down (red blink).
  GUI (previews/gui_optical_mux.png): Channels (ch, network, lanes, up) / Line (far end, distance, loss, pairing).

=====================================================================================================
3. OPTICAL AMPLIFIER - optical_amplifier (block: an 8 x 8 x 16 inline housing along the fibre axis) and _rack (1U)
=====================================================================================================
  Resets span loss; small power draw; unpowered = pass-through (no reset). States off / amplifying / input loss of signal
  (fault). HUD: input and output lanes, span length before and after. Art: block - recessed ports on both ends, a gain window
  on the side (static green gain LED); rack - orange type tab, input / output sockets, the gain bar on _on.

=====================================================================================================
4. OPTICAL TRANSPORT SHELF - optical_transport_shelf (6U)
=====================================================================================================
  Slots (models/block/rack_card/slot_positions.json "shelf": 10 vertical slots, texels on the front): 0-1 controller cards
  (redundant: the second takes over if the first fails), 2-9 line cards: transponder_card (1 client network -> 1 long-haul
  channel, 32 lanes), mux_card (up to 8 transponder channels onto the line), amplifier_card (resets span loss on the line side),
  protection_card (1+1: two separate paths - two fibre runs, or fibre + a Network Bridge pair; switch to protect within 1 tick
  when working fails, back when restored if revertive [setting]). Up to 40 channels per shelf [config]. Performance monitoring
  per span / channel: length, loss, lanes delivered, protection state, signal quality = 100 % - 4 % per lane lost (min 0 when
  down). Shelves pair end to end with a Link Card. Art: 10 slot blanks, a fibre-management tray along the bottom; controller
  cards carry the critical / major / minor alarm LED sockets. GUI: slot view (previews/gui_transport_shelf.png: the shelf's
  front at 1:1 with its cards - click a card for its settings), Channels, Spans.

=====================================================================================================
5. CHASSIS SWITCH - chassis_switch (10U)
=====================================================================================================
  Slots ("switch"): 2 supervisor (half-width, top row), 8 line (1U rows), 4 PSU (bottom row, quarter width). Active supervisor
  runs the switch; the standby takes over within 1 tick if it fails or is removed, without dropping traffic. Line cards:
  access_card (48 rack-local lanes, like an L2 Switch pool), uplink_card (4 Optical Transceiver cages, aggregate with failover
  like rack cable entries), routing_card (the L3 Switch's rules and QoS, higher limits; more cards add throughput), trunk_card
  (VLAN trunk ports - only once VLAN trunking ships). Runs on any one PSU; degraded below two (the _degraded status sheet).
  Everything an L3 Switch does is available through its cards; hot-swappable; removing a card affects only what it provided.
  GUI (previews/gui_chassis_switch.png): slot view + supervisor state, lanes, uplinks, PSUs.

=====================================================================================================
6. BLADE ENCLOSURE - blade_enclosure (10U)
=====================================================================================================
  Front: 16 half-height blade slots ("blade_front": 2 rows of 8). compute_blade (crafting threads: 8 per blade, vs a Compute
  Server's per-U rate - proposal 25 % more per rack unit), memory_blade (job buffer like a Memory Server), fabrication_blade
  (schematics + crafting like a Fabrication Server), storage_blade (2 Storage Drive bays). Rear: 2 interconnect_module (the lanes
  all blades use - blades don't take rack lanes; two = redundant), 6 blade_psu, 1-2 management_module (second = standby). Blades
  count toward the Rack Scheduler like their servers; Storage Blades count as network storage.
  GUI (previews/gui_blade_enclosure.png): Front / Rear slot views, per-blade status, Totals.

8. TERMINAL OS / ELCL (layouts/*.txt, previews/crt_*.png)
=====================================================================================================
  WRKHW (Work with Hardware, new): every chassis on the network with slots, cards, blades, PSUs and status; 5=Display 8=Locate.
  DSPOPT (Display Optical Status): multiplexers, amplifiers, shelves; spans, channels, loss, quality, protection.
| Command | Parameters | Context | Notes |
| `RTVCHSSTS` | `DEV`(Req) `RTNLIST`(Req, *LIST of 'slot part status') `RTNSTS`(*CHAR: *ONLINE *DEGRADED *FAULT) | all | ELC2701, ELC2702. |
| `RTVOPTSTS` | `DEV`(Req) `SPAN`(*FIRST \| name) `CHANNEL`(*ALL \| 1-40) `RTNLANES`(*INT) `RTNLOSS`(*INT) `RTNQUAL`(*INT %) `RTNPROT`(*CHAR) | all | ELC2701, ELC2703, ELC2704. |
| `CHGPROT` | `DEV`(Req) `SPAN`(Req) `PATH(*WORKING\|*PROTECT)` | I, B | build permission; for testing. ELC2701, ELC2703, ELC2705, ELC0401. |
Messages (ELC27xx): ELC2701 30 "Device &1 not found or not a chassis / optical device."  ELC2702 10 "Chassis &1 is degraded
(&2)."  ELC2703 30 "Span &1 not found on &2."  ELC2704 30 "Channel &1 is not assigned."  ELC2705 30 "Span &1 has no protect path."
Trigger events: *CARDFAULT, *SUPFAILOVER, *PROTSWITCH, *SPANLOSS (DATA = device, slot / span, detail).
